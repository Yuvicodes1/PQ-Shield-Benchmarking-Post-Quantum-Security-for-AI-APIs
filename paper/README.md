# PQ-Shield journal: figures, tables, and what still has to happen

Everything in this folder is generated by `python -m analysis.paper_figures`.
Re-run it after any new experiment; never edit the outputs by hand.

```
paper/
  figures/   *.pdf (vector, for LaTeX) + *.png (300 dpi, for Word/slides)
  tables/    *.tex (booktabs; add \usepackage{booktabs} to the preamble)
  key_numbers.md   every number the text should quote, with provenance and caveats
```

Outputs built from the concurrency sweep are stamped **PROVISIONAL** until you
regenerate with `--concurrency-run-id <id>` from a clean sweep (see section 3).

## 0. Configurations and workloads (state both in the paper)

| ID | Name | Key establishment | Signature | Quantum-safe KEX? |
|---|---|---|---|---|
| — | Control | none | none | — |
| A | Classical-RSA (legacy) | RSA-2048 OAEP, fresh key per handshake | ECDSA P-256 | no |
| A′ | **Classical-ECDHE** (new) | ephemeral X25519 | ECDSA P-256 | no |
| B | Hybrid | ML-KEM-768 | ECDSA P-256 | yes |
| C | Full PQC | ML-KEM-768 | ML-DSA-65 | yes |

A′ is the realistic classical baseline: TLS 1.3 removed RSA key transport, and
X25519 is the classical half of the X25519MLKEM768 group that browsers and CDNs
already negotiate. A′ and B have identical signature code, so A′→B isolates
X25519→ML-KEM-768. A's per-handshake RSA key generation is not how production
works; present A as a legacy/worst-case variant, not *the* classical baseline.

Note on naming: B is "PQ key exchange + classical signatures". In TLS literature,
"hybrid" usually means X25519+ML-KEM combined in the *key exchange*. Say which
one you mean in §IV.

**Workloads:** streaming experiments (strategy comparison, streaming HNDL,
sequence attacks) use the real **Llama-3.2-3B-Instruct** backend. The
concurrency sweep, payload profiles, single-transaction HNDL, and MITM use the
non-streaming endpoint with the **RandomForest** classifier (or the selected
payload profile). Running 1,000 concurrent Llama generations on one laptop
would measure the GPU queue, not the cryptography.

## 2. Corrections the draft needs

Status after the clean 2026-10-02 re-run. All numbers are in `key_numbers.md`; the

1. **Latency metric (§VI-A, H1, Limitations).** The draft compared `rtt_ms`, which
   leaves out the handshake round trip, against Control's single request. With end-to-end
   `total_ms` (and the fixed Control, item 16), at 10 connections: Classical-RSA +86.5%;
   Classical-ECDHE +4.9%; Hybrid +4.4%; Full PQC +3.3%; Hybrid-KEX +7.8%. The draft's
   "Hybrid −18.3% vs Control" was an artifact; drop it from Limitations and H1.
2. **Full PQC concurrency data** — ✅ now measured (5 reps × {10,100,1000}).
3. **"5,000/5,000 failed"** — ✅ resolved: on the 8-core M3, Classical-RSA at 1,000

4. **Primitive numbers** — ✅ re-measured with 200 RSA keygen samples: 6,167× (median)
   RSA-2048 vs ML-KEM-768 keygen; ML-DSA-65 verify 28,202 vs ECDSA 21,602 ops/s (1.31×).
   Replace 4,794× and 26,247/11,723 everywhere.
5. **Streaming numbers** — ✅ now real Llama-3.2-3B (run `20261002T152132`, 10 reps, 300
   transactions, 0 errors). 200 tokens: buffer-and-sign TTFT 4.9–5.3 s; per-chunk and
   hash-chain 125–133 ms (39–42×), indistinguishable from each other. Full PQC signature
   bytes 132,360 (per-chunk) vs 3,309 (hash-chain). Drop the synthetic 67.5 ms/29.6×/32.7×
   and the "hash-chain marginally beats per-chunk" claim.
6. **Classical buffer-and-sign 13 s TTFT** — ✅ fixed by the warm-up transaction; now
   4,927 ms, in line with the other configurations. No footnote needed.
7. **Streaming HNDL** — ✅ Llama: 11.4 B/token, R² = 0.9997 over 50–585 tokens, for both
   Classical-RSA and Classical-ECDHE; 0 B for all ML-KEM configurations. Drop "40× range"
   (the model ends long requests early).
8. **MITM** — ✅ fixed and re-run for all 5 protected configs (100 per target): 100% detected;
   AEAD rejects a flipped ciphertext bit in 0.007–0.008 ms, signature verification a flipped
   signature bit in 0.059–0.083 ms. The client now decrypts before verifying, matching report
   Fig 4.5 and §III-B. Report this in §VI (`tab_threats`, text in `results_section.tex`).
9. **Cross-references.** §V-B "Section V-D" (reordering) → V-E/VI-D. §V-F "Section VI-D"
   (HNDL exclusion) → VI-E. §IX-A "Section VI-D" (HNDL) → VI-E.

    session keys". None of the three configurations ratchet. Rephrase as future work.

13. **Payload-shape study** — ✅ now 5 reps × 6 configs × 4 profiles at 10 connections;

14. **References** — ✅ all verified; use `references.bib` (see `reference_audit.md`).
    Still to do by hand: replace the single-sentence [1]–[15] citation block in the intro.
15. **Front/back matter.** Dr. Nivitha is both a co-author and thanked in the
    Acknowledgment. Her grade is "Sr. Grade 1" here vs "Grade 2" in the report.
    Author e-mails are still `x@vit.com`. §III-3.1 hardware says the concurrency
    sweep ran on the single-core sandbox; state the actual host for each dataset

18. **Queueing bimodality at 100 connections.** Per-repetition medians of the non-RSA protected
    configurations fall near either ~1,000 or ~1,550 ms at random, so pooled medians cannot rank
    them at 100 connections. Say so (text in `results_section.tex`); the table now shows the
    per-repetition range.

16. **Control baseline was handicapped (now fixed).** Control's `/predict` was `async def`
    running the blocking model on the event loop, which serialized all requests. The protected
    endpoints run in FastAPI's thread pool. On the 2026-10-02 sweep, Control at 1,000 connections
    failed 52–66% of requests (ConnectError) while protected configs failed ~1.5%. At 100
    connections it served 38.9 req/s vs 106 req/s after the fix. Every "overhead vs Control" number
    computed before this fix, **including the draft's**, is biased toward the protected configs.
    Control was re-run with the fix (step 12); `paper_figures` uses each config's latest run.
17. **Classical-RSA does not collapse on a multi-core host.** On the 8-core M3, Classical-RSA at
    1,000 connections failed only 1.5% of requests, at 3.8 cores of server CPU (4.8 cores already
    at 10 connections). The draft's 100% failure was on a single-core sandbox. Reframe it as
    "per-handshake RSA key generation is CPU-bound and fails when cores run out", not as an
    inevitable failure.

## 3. Experiments to (re-)run

One command runs everything, in order, on this machine (~3 h), and records every
run_id in `results/paper_runs.json`. `analysis.paper_figures` then picks them up
with no flags:

```bash
caffeinate -i .venv/bin/python -m bench.paper_runs        # all 8 steps
.venv/bin/python -m bench.paper_runs --steps 6,7,8        # or a subset
```

| Step | What | Size |
|---|---|---|
| 1 | primitive micro-benchmark (incl. X25519; RSA keygen 200 samples) | ~3 min |
| 2 | concurrency matrix: 5 configs × {10,100,1000} × 5 reps | ~1.5–2 h |
| 3 | payload-shape sweep: 4 profiles × 5 configs × c=10 × 5 reps | ~10 min |
| 4 | network emulation: {loopback, metro, wan, mobile} × 5 configs × c=10 × 5 reps | ~15 min |
| 5 | single-transaction HNDL (1,000 req) + MITM ciphertext/signature (100 each), 4 configs | ~5 min |
| 6 | streaming strategies, real Llama: 4 configs × 3 strategies × {50,200} tok × 10 reps | ~20 min |
| 7 | streaming HNDL, real Llama: {50,200,500,2000} tok | ~10 min |
| 8 | streaming sequence attacks, real Llama: drop/reorder × 10 trials | ~10 min |

Before starting:
- **Plug in.** This Mac turns on Low Power Mode on battery, which throttles the CPU.
  Never switch power source mid-run.
- Stop the Streamlit app (port 8000) and leave the machine otherwise idle.
- Threat and validation results are archived to `results/archive/pre_rerun_*` first.

## 4. Code changes made for this

- **Control endpoint fix** (`api/server.py`): plain `def`, so it runs in the thread pool like
  the protected endpoints (see correction 16).
- **Checkpoint verification** (`crypto/streaming.py`, `api/secure_streaming_client.py`): the client
  now verifies hash-chain checkpoint signatures (it silently ignored them before) and records
  exposure (`max_unverified_chunks`, `max_verification_lag_ms`) and `n_signatures`.
  `bench.streaming_runner --checkpoint-intervals`, `threats.streaming_mitm_experiment --checkpoint-intervals`.
- **Session resumption** (`api/schemas.py`, `api/secure_app.py`, `api/secure_client.py`): optional
  `keep_session` and kex-less resumed requests; `bench.orchestrator --requests-per-handshake N`.
  The old `--reuse-handshake` path never worked (the server forgot the handshake after one request).
- **Configuration B′, Hybrid-KEX** (`crypto/hybrid_kex.py`, `api/server_config_hybridkex.py`):
  X25519MLKEM768 + ECDSA P-256.
- New outputs: `fig_checkpoint_frontier`, `tab_checkpoint`, `fig_handshake_amortization`.

- **Network emulation:** `bench/netem_proxy.py` (unprivileged TCP proxy: RTT/2 delay
  each way + shared per-direction bandwidth); `bench.orchestrator --network-profile
  {localhost,metro,wan,mobile}`; `network_profile` column in raw CSVs.
- **One-shot driver:** `bench/paper_runs.py` (steps above, manifest, archiving).
- **New outputs:** `fig_payload_profiles`, `tab_payload_profiles`, `fig_network_conditions`,
  `tab_resources` (server CPU/RSS per config × concurrency).
- **References:** `references.bib` (all entries verified), `reference_audit.md`
  (what was wrong in the draft, plus missing prior art), `text_additions.tex`
  (drop-in Related Work, configuration table, network method, Limitations).

- **New configuration A′, Classical-ECDHE** (`crypto/classical_ecdhe.py`,
  `api/server_config_ecdhe.py`, config key `classical-ecdhe` / crypto name
  `classical_ecdhe`), wired through the orchestrator, streaming runner, threat
  experiments, trade-off matrix (security score 0.0), dashboard, and paper
  figures. `validation/primitive_bench.py` now also times X25519 keygen and
  exchange. Covered by the existing parametrized round-trip, tamper, and streaming
  tests (13 new test cases, all passing).

- `bench/orchestrator.py`: raw filenames now carry the run_id and payload profile. Before,
  every sweep (including dashboard smoke tests) overwrote `{config}-c{N}-r{rep}.csv`,
  which is how the headline data got mixed. Host info is now recorded per cell.
- `analysis/aggregate.py`: `--run-id` filter; `total_ms` is the primary significance
  metric; cells where every request failed now appear with their error rate instead
  of vanishing.
- `analysis/tradeoff_matrix.py`: scores on `total_ms`; failed cells are kept and marked
  `available=False`.
- `api/secure_client.py`: AEAD decrypt runs before signature verify (matches the
  design), and is timed on its own (`aead_decrypt_ms`).
- `threats/mitm_experiment.py`: detection time is the rejecting check alone; adds
  median and standard deviation.
- `validation/primitive_bench.py`: ≥50 RSA keygen samples; median-based ratio; host info.
- `bench/streaming_runner.py`: records the backend per row; discarded warm-up generation;
  optional `--shuffle-seed`.
- Results Dashboard: latency chart, significance table, and trade-off slider use
  end-to-end latency.
